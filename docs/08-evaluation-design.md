# ForgeRAG RAG 自动化评测设计

## 1. 文档目的

本文档用于定义 ForgeRAG 第一版 RAG 自动化评测设计，承接已有需求、架构、数据库、API、RAG 核心链路和 Agentic RAG 设计。

本文档重点说明：

1. 评测数据集、评测样本、评测任务和评测结果如何协作。
2. 如何批量执行基础 RAG 或 Agentic RAG 问答。
3. 如何记录检索结果、生成答案、引用来源和评分结果。
4. 如何通过评测结果优化切分策略、检索参数、Rerank 策略、Prompt 版本和问答模式。
5. 如何关联 `qa_record_id`、`agent_run_id`、`trace_id` 和评测结果。

本文档不重复展开 RAG 问答流程、Agentic RAG 节点、API 字段和数据库表字段细节。

------

## 2. 设计边界

### 2.1 覆盖范围

第一版评测模块覆盖：

```text
创建评测集
  → 添加评测样本
  → 创建评测任务
  → 批量执行问答
  → 保存样本级结果
  → 记录评分
  → 汇总任务结果
  → 关联 Trace
```

### 2.2 不覆盖范围

第一版暂不实现：

1. 完整实验管理平台。
2. 可视化评测大屏。
3. A/B Testing 平台。
4. 复杂指标仪表盘。
5. 自动调参系统。
6. 评测数据集版本管理。
7. 复杂人工审核流。
8. 独立模型训练或微调评测。

------

## 3. 核心对象

| 对象       | 数据表                | 说明                                    |
| ---------- | --------------------- | --------------------------------------- |
| 评测数据集 | `evaluation_datasets` | 组织一组评测样本                        |
| 评测样本   | `evaluation_samples`  | 保存问题、参考答案、期望引用和标签      |
| 评测任务   | `evaluation_tasks`    | 保存一次批量评测的配置和状态            |
| 评测结果   | `evaluation_results`  | 保存单条样本执行结果、评分和 Trace 关联 |

对象关系：

```text
evaluation_datasets
  └── evaluation_samples

evaluation_tasks
  └── evaluation_results
        ├── qa_record_id
        ├── agent_run_id
        └── trace_id
```

------

## 4. 评测数据集设计

### 4.1 数据集职责

评测数据集用于管理一组可重复执行的评测问题。

数据集应支持：

1. 按知识库或业务场景组织样本。
2. 保存数据集名称、描述和状态。
3. 支持样本增删改查。
4. 支持后续创建多个评测任务。
5. 支持不同配置下重复运行。

### 4.2 数据集状态

第一版建议使用：

```text
active
disabled
deleted
```

说明：

1. `active` 数据集可以创建评测任务。
2. `disabled` 数据集暂不可用于新任务。
3. `deleted` 表示软删除，不在普通列表中展示。

------

## 5. 评测样本设计

### 5.1 样本内容

评测样本是评测任务的最小输入单元。

核心内容：

| 字段                    | 说明                   |
| ----------------------- | ---------------------- |
| `question`              | 评测问题               |
| `reference_answer`      | 参考答案，可为空       |
| `expected_document_ids` | 期望命中文档，可为空   |
| `expected_chunk_ids`    | 期望命中 chunk，可为空 |
| `tags`                  | 问题标签               |
| `difficulty`            | 难度标记               |
| `metadata`              | 扩展信息               |

### 5.2 样本设计原则

1. `question` 必填。
2. `reference_answer` 用于回答质量评估。
3. `expected_chunk_ids` 用于检索命中评估。
4. `tags` 用于按问题类型分析结果。
5. `difficulty` 用于区分简单、普通和复杂问题。
6. 第一版不做复杂样本版本管理。

### 5.3 样本分类建议

第一版可使用以下标签：

```text
retrieval
answer
citation
refusal
agentic
easy
medium
hard
```

标签只用于分析和过滤，不参与核心业务判断。

------

## 6. 评测任务设计

### 6.1 任务职责

评测任务用于基于指定数据集和配置批量执行问答。

任务创建时需要保存配置快照：

| 配置                | 说明                        |
| ------------------- | --------------------------- |
| `dataset_id`        | 评测数据集                  |
| `knowledge_base_id` | 目标知识库                  |
| `qa_mode`           | `basic_rag` / `agentic_rag` |
| `retrieval_config`  | 检索参数                    |
| `rerank_config`     | Rerank 参数                 |
| `model_config`      | 模型参数                    |
| `prompt_version`    | Prompt 版本                 |

### 6.2 任务状态

评测任务状态：

```text
pending → running → completed
                 ├── failed
                 └── cancelled
```

状态说明：

| 状态        | 说明             |
| ----------- | ---------------- |
| `pending`   | 已创建，未执行   |
| `running`   | 正在执行         |
| `completed` | 全部样本执行完成 |
| `failed`    | 任务级失败       |
| `cancelled` | 已取消           |

### 6.3 任务统计

任务执行过程中应更新：

1. `total_count`
2. `success_count`
3. `failed_count`
4. `average_score`
5. `started_at`
6. `finished_at`
7. `error_message`

------

## 7. 评测执行流程

### 7.1 执行入口

评测任务由接口手动触发。

第一版不要求定时调度，也不要求复杂后台队列。

### 7.2 执行流程

```text
1. 校验评测任务是否存在
2. 校验任务状态是否允许执行
3. 校验数据集和知识库状态
4. 读取评测样本
5. 将任务状态更新为 running
6. 遍历样本
7. 根据 qa_mode 调用基础 RAG 或 Agentic RAG
8. 保存单条 evaluation_result
9. 更新成功数和失败数
10. 汇总平均分
11. 更新任务状态为 completed
12. 记录 trace_id 和结构化日志
```

### 7.3 执行模式

| `qa_mode`     | 调用链路                  |
| ------------- | ------------------------- |
| `basic_rag`   | 调用基础 RAG 问答流程     |
| `agentic_rag` | 调用 Agentic RAG 问答流程 |

执行要求：

1. 每条样本应独立执行。
2. 单条样本失败不应直接导致整个任务失败。
3. 任务级依赖异常可以导致任务失败。
4. 样本级失败必须保存失败原因。
5. 每条结果应尽量关联 `qa_record_id` 和 `trace_id`。
6. Agentic RAG 结果还应关联 `agent_run_id`。

------

## 8. 评测结果设计

### 8.1 结果内容

每条评测结果至少保存：

| 内容                         | 说明                  |
| ---------------------------- | --------------------- |
| `eval_task_id`               | 所属任务              |
| `eval_sample_id`             | 所属样本              |
| `question_snapshot`          | 问题快照              |
| `reference_answer_snapshot`  | 参考答案快照          |
| `generated_answer`           | 实际生成答案          |
| `retrieval_results_snapshot` | 检索结果摘要          |
| `citations_snapshot`         | 引用摘要              |
| `status`                     | 样本执行状态          |
| `score`                      | 综合分                |
| `metric_scores`              | 多维评分              |
| `error_message`              | 失败原因              |
| `qa_record_id`               | 关联问答记录          |
| `agent_run_id`               | 关联 Agentic RAG 执行 |
| `trace_id`                   | 关联 Trace            |
| `latency_ms`                 | 执行耗时              |

### 8.2 快照原则

评测结果应保存必要快照，而不是只保存外键。

原因：

1. 问答记录后续可能被清理。
2. chunk 可能因文档重新处理而变化。
3. Prompt 和模型配置可能变化。
4. 评测结果需要支持复盘和对比。

第一版快照只保存摘要，不保存完整 Trace。完整链路细节仍由 Langfuse 管理。

------

## 9. 评测指标设计

### 9.1 指标总览

第一版评测指标分为四类：

| 类别     | 指标                                   |
| -------- | -------------------------------------- |
| 检索质量 | 检索命中率、最高检索得分、平均检索得分 |
| 回答质量 | 回答准确性、忠实性、完整性             |
| 引用质量 | 引用命中、引用相关性、引用是否支撑答案 |
| 运行质量 | 耗时、Token 消耗、失败率、拒答合理性   |

### 9.2 检索质量指标

| 指标                  | 说明                     |
| --------------------- | ------------------------ |
| `retrieval_hit`       | 是否命中期望文档或 chunk |
| `top1_hit`            | 第一条结果是否命中期望   |
| `top_k_hit`           | 前 K 条是否命中期望      |
| `max_retrieval_score` | 最高检索得分             |
| `avg_retrieval_score` | 平均检索得分             |

适用前提：

1. 样本配置了 `expected_document_ids` 或 `expected_chunk_ids`。
2. 没有期望引用时，只记录分数，不计算命中率。

### 9.3 回答质量指标

| 指标                  | 说明                 |
| --------------------- | -------------------- |
| `answer_correctness`  | 回答是否接近参考答案 |
| `faithfulness`        | 回答是否忠实于上下文 |
| `answer_completeness` | 回答是否覆盖关键要点 |
| `refusal_correctness` | 拒答是否合理         |

第一版可支持人工评分或规则评分，LLM-as-Judge 作为后续扩展。

### 9.4 引用质量指标

| 指标                 | 说明                 |
| -------------------- | -------------------- |
| `citation_hit`       | 引用是否命中期望来源 |
| `citation_relevance` | 引用是否与问题相关   |
| `citation_support`   | 引用是否能支撑答案   |
| `citation_count`     | 引用数量             |

引用质量评估重点是：答案引用是否来自实际上下文，且是否能支撑回答。

### 9.5 运行质量指标

| 指标            | 说明         |
| --------------- | ------------ |
| `latency_ms`    | 单样本耗时   |
| `input_tokens`  | 输入 token   |
| `output_tokens` | 输出 token   |
| `failed`        | 是否执行失败 |
| `error_type`    | 失败类型     |
| `trace_id`      | 链路追踪标识 |

## 10. 评分方式

### 10.1 第一版评分来源

第一版支持三种评分来源：

| 来源        | 说明                   |
| ----------- | ---------------------- |
| `rule`      | 规则评分               |
| `manual`    | 人工评分               |
| `llm_judge` | LLM 自动评分，后续扩展 |

### 10.2 规则评分

规则评分适合计算客观指标：

1. 是否命中期望文档。
2. 是否命中期望 chunk。
3. 是否返回引用。
4. 是否成功生成答案。
5. 是否按预期拒答。
6. 是否超过耗时阈值。

### 10.3 人工评分

人工评分用于主观指标：

1. 回答准确性。
2. 回答完整性。
3. 引用是否真正支撑答案。
4. Agentic RAG 决策路径是否合理。

第一版只需要在数据结构中保留人工评分字段或 `metric_scores` 扩展，不必开发完整审核后台。

### 10.4 综合分

综合分建议以 `0 - 1` 表示。

示例：

```text
score = 0.4 * retrieval_score
      + 0.4 * answer_score
      + 0.2 * citation_score
```

权重不应硬编码，应作为评测配置或后续扩展项。

------

## 11. 配置对比设计

评测任务应支持对比不同配置效果。

常见对比维度：

| 维度        | 示例                          |
| ----------- | ----------------------------- |
| 切分策略    | `chunk_size`、`chunk_overlap` |
| 检索参数    | `top_k`、`score_threshold`    |
| Rerank 策略 | 是否启用、`top_n`             |
| Prompt 版本 | `rag_qa_v1`、`rag_qa_v2`      |
| 问答模式    | `basic_rag`、`agentic_rag`    |
| 模型配置    | 模型名称、temperature         |

第一版只需要保存配置快照并支持查询结果，不需要做复杂对比报表。

------

## 12. Trace 关联设计

### 12.1 关联对象

评测结果应关联：

```text
evaluation_result
  ├── qa_record_id
  ├── agent_run_id
  └── trace_id
```

### 12.2 关联目标

通过这些标识可以追踪：

1. 最终问答记录。
2. 引用快照。
3. Agentic RAG 节点执行摘要。
4. Langfuse Trace。
5. 结构化日志。

### 12.3 降级要求

如果 Langfuse 不可用：

1. 评测任务应尽量继续执行。
2. `trace_id` 可以为空。
3. 评测结果仍需保存问答结果和错误信息。
4. 结构化日志应记录观测组件异常。

------

## 13. 异常处理

### 13.1 样本级异常

样本级异常不会中断整个任务。

| 异常             | 处理方式                                 |
| ---------------- | ---------------------------------------- |
| 检索为空         | 保存拒答或空检索结果                     |
| 模型调用失败     | 当前样本标记为 `failed`                  |
| Rerank 降级      | 当前样本可继续执行                       |
| Agentic RAG 拒答 | 当前样本标记为成功执行，但业务结果为拒答 |
| 引用为空         | 保存结果并降低引用评分                   |

### 13.2 任务级异常

任务级异常会导致任务失败。

| 异常                 | 处理方式                   |
| -------------------- | -------------------------- |
| 评测任务不存在       | 返回 `EVAL_TASK_NOT_FOUND` |
| 数据集不存在或不可用 | 任务不启动                 |
| 知识库不存在或不可用 | 任务不启动                 |
| 数据库异常           | 任务标记为 `failed`        |
| 配置非法             | 任务标记为 `failed`        |
| 执行器初始化失败     | 任务标记为 `failed`        |

### 13.3 状态一致性

异常发生时必须保证：

1. 评测任务最终不应长期停留在 `running`。
2. 已完成样本结果应保留。
3. 样本失败原因应写入 `evaluation_results`。
4. 任务级失败原因应写入 `evaluation_tasks.error_message`。
5. 可恢复异常不应影响其他样本继续执行。

------

## 14. 删除与清理策略

删除策略与数据库设计保持一致：

| 对象                  | 策略         |
| --------------------- | ------------ |
| `evaluation_datasets` | 软删除       |
| `evaluation_tasks`    | 软删除       |
| `evaluation_samples`  | 默认物理删除 |
| `evaluation_results`  | 默认物理删除 |

说明：

1. 评测集和评测任务属于核心实验资产，保留软删除。
2. 样本和结果属于明细数据，不建议长期软删除。
3. 删除评测任务时，后续可级联物理清理 `evaluation_results`。
4. 需要长期保留的重要评测结果，后续可扩展归档机制。

------

## 15. 可观测性要求

评测模块应记录：

| 阶段        | 记录内容                           |
| ----------- | ---------------------------------- |
| 任务创建    | 数据集、知识库、问答模式、配置快照 |
| 任务执行    | 开始时间、结束时间、样本数量       |
| 样本执行    | 问题、状态、耗时、失败原因         |
| 检索阶段    | 召回数量、最高得分、命中情况       |
| 生成阶段    | 回答、引用、Token、模型名称        |
| Agentic RAG | `agent_run_id`、节点摘要、最终状态 |
| 结果汇总    | 成功数、失败数、平均分             |

记录原则：

1. PostgreSQL 保存评测业务结果。
2. Langfuse 保存完整链路细节。
3. 结构化日志保存任务执行过程。
4. 不在日志中记录密钥。
5. 失败样本必须可通过 `trace_id` 或业务 ID 追踪。

------

## 16. 测试要求

第一版至少覆盖：

| 测试类型     | 测试内容                    |
| ------------ | --------------------------- |
| 数据集测试   | 创建、查询、软删除          |
| 样本测试     | 添加、查询、物理删除        |
| 任务测试     | 创建、启动、状态流转        |
| 执行测试     | 批量执行基础 RAG            |
| Agentic 测试 | 批量执行 Agentic RAG        |
| 结果测试     | 保存问答、引用、评分、Trace |
| 指标测试     | 命中率、综合分、失败率      |
| 异常测试     | 单样本失败不阻断任务        |
| 配置测试     | 配置快照正确保存            |
| 清理测试     | 任务清理时结果可物理删除    |

外部模型、Qdrant 和 Langfuse 应支持 mock 或测试替身。

------

## 17. 第一版实现范围

第一版必须实现：

1. 评测数据集创建、查询和软删除。
2. 评测样本添加、查询和删除。
3. 评测任务创建、启动和状态查询。
4. 支持 `basic_rag` 评测。
5. 支持 `agentic_rag` 评测。
6. 保存任务配置快照。
7. 保存样本级执行结果。
8. 保存检索结果摘要。
9. 保存生成答案和引用摘要。
10. 保存 `qa_record_id`、`agent_run_id` 和 `trace_id`。
11. 支持基础规则评分。
12. 统计成功数、失败数和平均分。
13. 支持失败原因记录。
14. 支持结果查询。

第一版暂不实现：

1. 完整实验平台。
2. A/B Testing。
3. 可视化报表。
4. 复杂数据集版本管理。
5. 自动调参。
6. 完整人工审核后台。
7. 强依赖 LLM-as-Judge。
8. 评测结果归档表。

------

## 18. 设计总结

ForgeRAG 第一版评测设计的核心目标是：用轻量、可复现、可查询的方式评估 RAG 和 Agentic RAG 链路质量。

设计重点如下：

1. 用评测集组织样本。
2. 用评测任务保存配置快照。
3. 用评测结果记录样本级执行过程。
4. 用 `qa_record_id`、`agent_run_id` 和 `trace_id` 关联问答、Agent 和观测数据。
5. 优先支持基础规则评分和人工评分扩展。
6. 暂不构建复杂实验平台。
7. 保证评测结果能够指导切分、检索、Rerank、Prompt 和 Agentic RAG 流程优化。
